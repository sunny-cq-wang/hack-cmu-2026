# AGENTS.md — PetPlate

> Read this file completely before touching any code. It is written for AI coding agents with a limited context window. Every rule here exists to let four agents work in parallel without breaking each other's code.

## 1. What this project is

PetPlate is a mobile app (Expo / React Native) plus a TypeScript API that links a person's diet to their pet's diet. Both run the same daily loop: log intake → compare to a computed target → earn a shared daily score → keep a streak. The pet's avatar (generated by Grok Imagine from the owner's real pet photo, animated with Rive) visibly thrives or droops based on the *combined* score. Meal photos are analyzed by a Grok vision model; nutrients (including micronutrients) come from USDA FoodData Central; the pet can "talk" via Grok Voice.

Hackathon track: **Food**. Sponsor tracks we are targeting: **xAI (Grok Voice / Imagine)**, **Auth0**, **MongoDB Atlas**.

## 4. Non‑negotiable conventions

1. **TypeScript strict everywhere.** No `any` without an inline `// why:` comment.
2. **All request/response shapes come from `@petplate/shared`.** Import the zod schema, call `.parse()` at the boundary (API handler input, mobile API client output). Never hand-write a duplicate interface.
3. **Server owns all math.** The mobile app never computes calories, targets, scores, or portions. It displays what the API returns.
4. **Every external call has a timeout and a fallback.** Grok vision: 8 s timeout → cached demo result. USDA: 4 s → Grok's own estimate. Imagine: async with polling, never blocks a request. Voice: 15 s → text-only reply.
5. **Env vars are read only in `apps/api/src/config.ts` and `apps/mobile/src/lib/config.ts`.** Nothing else calls `process.env`.
6. **Dates:** store `Date` in Mongo (UTC). "Day" boundaries use the user's `timezone` field (IANA string) via `date-fns-tz`. Day keys are `YYYY-MM-DD` strings in the user's timezone.
7. **IDs:** Mongo `ObjectId` in the DB, serialized as strings in every API payload (`id`, never `_id`, in responses).
8. **Errors:** API returns `{ error: { code: string, message: string } }` with an appropriate status. Codes are listed in `API_CONTRACTS.md`.
9. **Logging:** `apps/api/src/lib/log.ts` (pino). Log every external API call with duration and success/failure. No `console.log` in committed code.
10. **Demo safety:** anything that could fail live must have a `DEMO_MODE=true` path that returns a canned result. See `TIMELINE_AND_DEMO.md`.
11. **Commits:** small, prefixed with your owner tag: `P3: adaptive pet loop`. Push to your own branch `p3/<feature>`; merge to `main` only at checkpoints or when green.
12. **No secrets in the repo.** `.env` is git‑ignored. `.env.example` lists every key.

## 5. How to run

```bash
pnpm install
cp .env.example .env            # fill in keys
pnpm --filter @petplate/shared build
pnpm --filter api dev           # http://localhost:3000, hot reload
pnpm --filter mobile start      # Expo; press 'a' or 'i'. Requires a DEV BUILD (see ARCHITECTURE.md §4).
pnpm test                       # vitest across workspaces
pnpm typecheck                  # tsc --noEmit across workspaces
```

## 8. Things agents get wrong on this project — read twice

- **Expo Go cannot run this app.** Auth0, Rive, and the audio pipeline need native modules. Use `npx expo run:android` / `run:ios` or an EAS dev build. Do not "fix" a native-module error by removing the module.
- **Grok model names change.** Read `GROK_VISION_MODEL`, `GROK_CHAT_MODEL`, `GROK_IMAGE_MODEL`, `GROK_VIDEO_MODEL`, `GROK_TTS_MODEL`, `GROK_STT_MODEL` from env. Never hard-code a model string.
- **The xAI API is OpenAI-compatible at `https://api.x.ai/v1`.** Use the `openai` npm package with `baseURL` set. For Imagine and Voice endpoints that the OpenAI SDK doesn't wrap, use `fetch` directly (see `INTEGRATIONS.md`).
- **USDA returns values per 100 g.** Always scale by `grams / 100`. Nutrient IDs are in `INTEGRATIONS.md` §3.
- **Pet portioning uses IDEAL weight, not current weight**, for weight-loss pets. See `ALGORITHMS.md` §3.
- **Scores are computed server-side once per write** (meal saved, feeding saved, weigh-in saved) and stored in `dailyScores`. `/me/today` reads them; it does not recompute.
- **Avatar state comes from `/me/today.avatarState`.** The Rive component maps that string to a numeric `happiness` input. It never decides mood itself.
